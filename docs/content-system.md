# lizheng.ai内容系统

本文档说明个人网站各页面的任务、事实来源与更新边界，避免个人品牌、Superlinear产品站和GitHub之间重复或漂移。

## 一条主线

个人主页只争取留下一件事：

> **MAKE WHAT LASTS.**
>
> **学点真本事，做点真东西。**

中文个人主线是`学点真本事，做点真东西`：拿掉学历、title与平台以后，什么能力还成立；拿掉老师、老板和内部评分以后，做的东西还有没有人需要。Superlinear在机构层面承接后半句`做点真东西`；英文`MAKE WHAT LASTS`继续追问，这份价值经过时间以后是否仍被选择。这不是两套品牌，而是同一条从能力、制作到现实与时间的主线。

中文视觉名称使用`立正`；`课代表立正`继续作为已经建立内容认知的频道、播客与搜索名称。主页、metadata与结构化数据同时保存`孙煜征`、`立正`、`课代表立正`与`Yuzheng Sun`之间的关系，但不让四个名字在视觉上争夺主次。

`真东西`不是作者给自己颁发的真诚奖章，而是一个判断已经离开脑子和内部记分牌，成为用户、市场、事实或后果能够使用、检验、拒绝、改进或继续选择的东西。`做出你的代表作`保留为长期向往，不再是中文主签名，也不是课程或会员的结果承诺。

完整思想源与关于页保留下面这些性质不同、彼此作用的关系。首页不要求访客先学完它们：

- 世界模型、预测与证伪，尽力让更多理解变得显性、可挑战；
- craft在规则无法完整压缩、却仍需对结果负责的复杂性中继续更新同一份理解；两者彼此渗透和修正；
- `understand → internalize → conviction → build`解释理解在需要下注时怎样进入行动；
- 负责任的作者性，让作品的目的、标准、取舍与后果始终有人承担；
- 现实持续检验，时间逐渐显露什么继续重要，但两者都不是无误的终审。

代表作也不总从conviction开始。人可能先进入迷雾、动手并失败，再从预期与结果的差距里逐渐知道自己相信什么。这种非线性是整个解释成立的重要部分，但不是又一根品牌支柱。系统、制度、维护和分发可能是输入、craft的一部分或作品本身；复利才是可能结果。

## 首页的阅读顺序

1. **立正是谁。** 母题、简短的当前工作、可读的职业信息和Acquired真实合照；免费社区与访谈两个入口。
2. **正在做什么。** Superlinear Academy的开放社区先出现；AI Builders和Stay作为两个简短产品入口；企业合作保留独立现场、合作方式和参考价。
3. **和谁聊什么。** 精选嘉宾、所属机构和节目先于长方法论；保留200+场公开对话与40万+关注者的不同含义。
4. **怎么走到这里。** 一段有选择和代价的经历、一条简短履历线，以及2021→2023的可检查公开判断。完整经历与理念去关于页。
5. **有什么值得读。** Knowledge Bank文章原题、简短阅读理由、两本书及公开资料库，不重复写一遍总摘要。
6. **我从哪里参与。** 免费社区与合作入口，不要求访客先理解抽象框架才能开始。

2026-09-04的取舍是减少重复解释，不削弱履历、机构、作品与真实人物的分量。原首页的完整理念区由`DefiningWork.tsx`在关于页承接；个人思想owner没有因页面减法而被改写。桌面上的写作与书仍是两个可辨章节，阅读任务相邻。

详细页面结构见`docs/homepage-narrative-outline.md`。

### 最近文章的角色

首页的“最近在写”优先从公开Knowledge Bank选文。Knowledge Bank收录经过打磨、愿意长期保留的高质量文章；普通社区帖只在被正式收入Knowledge Bank，或当前页面有明确、不可替代的时效性需要时使用。

当前三篇文章共同回答：AI让更多事变容易以后，什么能力反而更重要：

- `Fake work`把“真东西”的反面说清楚：AI既能减少工作与结果之间的interface tax，也能让组织更便宜地制造忙碌证据。
- `AI-native人才`是当前的人才与工作研究：从结果出发，识别AI改变的能力与相对成本，重新设计做法，并继续对结果负责。它不是按年龄、工具数量或token用量划分人的身份标签。
- `名词与动词`区分工具知识与项目能力：名词有边界、文档和学习checkpoint，真实项目还要靠分解、判断、路由、诊断和迭代才能做成。

文章可以随研究更新而轮换。轮换看文章本身的质量，以及它能否让访客更快看懂母题怎样进入工作、人才、学习、产品或组织实践；发布时间只是次要信号。

## 权威如何出现

首页遵循`show → frame → let the reader conclude`：

1. **母题和真实作品建立向往。** 首页不解释整套思想；关于页保留敬佩的创造者与作品，供愿意深入的访客阅读。他们不为立正或Superlinear背书。
2. **个人经历证明真诚、下注与能力。** 它们不把创始人提前放进伟人的成就序列。
3. **产品与数字建立当下可信度。** 3,000+与Maven公开评分5.0/5回答教学采用与满意度；OpenAI、Anthropic与Google学员的公开评价说明有经验的人为何仍来学习；DoorDash现场回答工作能否进入真实组织；200+场对话回答一手输入与网络从哪里来。
4. **证据放在问题发生处。** 学员数字跟着AI Builders，社区行为跟着免费社区，WSJ书单跟着书。
5. **解释必要的一步。** 让非专业读者明白鸭哥的论文发表于AI顶会；不把每个事实都解释成“所以我们厉害”。
6. **作品与时间保留最终判决。** 雇主不是个人背书，流量不是观点正确，公开判断也不等于永远看得准，产品目的不等于保证成员结果。

### 2026年9月子页面梳理

主线是让访客容易找到内容，并从实际作品、经历和第三方反应形成判断。各页不重复宣讲主页母题：关于页用第一人称介绍经历与学院，书页先区分两本书各自回答的问题，合作页解释团队需要改变什么，课件页尽早进入列表，访谈目录同时支持人名与单集话题搜索。详细取舍见`subpage-review-2026-09-04.md`。

### Deck索引

- `shared/deck-index.ts`只保存已经决定对外展示的卡片信息、公开状态与正式分享链接，是主站Deck索引的唯一列表源。
- 同一场材料同时有deck和公开实录时，`href`/`linkKind`保存主入口，`secondaryHref`/`secondaryLinkKind`保存第二入口；不要拆成两张卡重复计数。
- 每套deck的源文件、版本历史、讲者笔记与客户交付仍由原项目维护；个人站只做索引，不复制deck，也不成为第二个内容owner。
- 同一客户的旧版、交付副本、Demo子deck与销售提案不重复计数。链接必须指向当前公开版本或明确标注的现场版；没有可靠公开入口时，宁可链接公开实录或标记“公开版整理中”，也不把旧版冒充最新版。
- 进入索引会显著提高可发现性。客户内部问卷、采购文件、报价、原始转录与未脱敏案例，即使已有技术上可访问的URL，也不因此自动进入列表。
- 页面按受众面临的问题分类，不按客户Logo堆墙。卡片回答四件事：为谁做、当时要解决什么、使用什么语言、从哪里打开。

## GitHub的任务

GitHub不复制整页人物宣言。它回答一个更窄的问题：这个人公开做出了什么，愿意把哪些系统交给别人使用？

Profile README只需要一句身份、当前工作、精选公共项目、书与公开内容入口、Seattle和联系方式。置顶仓库优先选择真实可用、边界清楚、README完整的工具，不按stars机械排序。
