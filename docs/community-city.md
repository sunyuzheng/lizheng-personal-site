# 社区地图：「我们在建一座城」

首页紧跟代表作的一段。每个点是超线性学院社区里的一位真实成员；成员按发帖和评论排序，最活跃的人在城中心、最亮。鼠标移到点上能看到这位成员的名字、哪个月加入、发过多少帖子和评论，点开就是TA在Circle上的公开主页；地图上方可以按名字找人，也可以随机遇见一位成员。

它回答的是代表作之后最自然的问题：这件事有多少人真的在参与。人数是实数，亮度是真实的参与度，每个点都是一个能点开的人，所以它不是装饰动画。

2026-09-30决定：所有成员的点都可以点开，名字公开显示、可以搜索。

2026-10-01决定：每个点同时显示成员的加入月份、帖子数和评论数。社区内容立正可以自由使用，地图展示成员信息没有隐私顾虑；此前「精确的帖子数不写进文件」的规则作废。

## 数据从哪里来、多久更新

- 数据来自Circle Admin API的成员列表（`community_members`），一次快照需要「成员数÷100」次请求，2026年9月底约246次。
- Data API不能替代它：Data API给的是行为事件，没有成员的名字和公开主页id。而加入时间、帖子数、评论数本来就在成员列表里，显示它们不增加任何请求。
- GitHub Actions每月1日北京时间10:00自动跑一次（`.github/workflows/community-city.yml`），生成数据、上传到Vercel Blob、再把线上文件读回来核对。也可以在GitHub的Actions页面手动运行。定时运行时如果线上数据还不到20天（例如月底刚手动跑过），就直接跳过，不调用Circle API。
- 网站在浏览器里读取Blob上的文件，所以每月更新数据不需要重新部署。

## Circle Admin API预算

- Admin API的月度额度和其他超线性工具共用。规则在`superlinear/1-会员社区/circle-data-analytics`的`docs/data-refresh-and-measurement.md`：先预留最坏请求数，默认2,400次硬停止，并保留至少600次应急空间。本任务每月预留300次。
- `--max-requests`（默认300）是硬上限：成员超过30,000人时脚本不会开始，需要先调高预算。
- `--dry-run`只用1次请求，报出成员数和所需请求数；如果Circle返回额度相关的响应头，也会打印出来。
- 中途失败不会覆盖线上数据：返回的成员少于总数的98%时不写文件；新快照比线上少10%以上时不上传（确认无误可以加`--force`）。

## 需要的密钥

| 名称                    | 用途                                   | 放在哪里                                                        |
| ----------------------- | -------------------------------------- | --------------------------------------------------------------- |
| `CIRCLE_ADMIN_API`      | Circle Admin API v2令牌                | GitHub仓库的Actions secret；本地运行时放在`.env`                |
| `BLOB_READ_WRITE_TOKEN` | 写入Vercel Blob（`lizheng-community`） | GitHub仓库的Actions secret；本地由`vercel link`写进`.env.local` |

两个文件都在`.gitignore`里。工作流的日志只打印成员数和热度分布，不打印名字。

## 数据格式

`scripts/build-community-city.ts`生成一个JSON文件，本地在`client/public/community/city.json`（不进Git），线上在Blob的`community/city.json`：

```json
{ "version": 1, "generatedAt": "2026-10-01", "count": 24531, "heat": "9987…000", "linked": ["452cd000", …], "names": ["立正", …], "joined": [202303, …], "posts": [12, …], "comments": [48, …] }
```

- 成员按活跃度从高到低排序；`heat`每位成员一个数字（0–9）。
- 活跃度 = 帖子数×3 + 评论数。有发帖或评论的成员热度为3–9（分档：1、3、10、30、100、300、1000）；没有的成员按最近一次访问给0–2（30天内为2，180天内为1）。
- `linked[i]`是第i位成员的公开主页id，`names[i]`是TA在Circle上显示的名字。名字像邮箱或电话号码时留空，页面上显示「打开TA的主页」。
- `joined[i]`是加入月份（YYYYMM，未知为0）；`posts[i]`、`comments[i]`是帖子数和评论数。成员按活跃度排序，所以这两个数组在最后一位有帖子或评论的成员处结束，之后的成员都是0。
- 地图用不到邮箱、其他资料字段和访问时间，所以不写进文件。
- 2026年10月之前的快照没有`joined`、`posts`、`comments`，页面只显示名字；11月1日的定时快照起自动带上。
- 文件估计约800KB；Blob用Brotli压缩传输，估计约230KB（加入月份和帖子、评论数约占30KB）。

需要立刻移除某个人时，把线上`city.json`里对应的id和名字改成空字符串，再用`vercel blob put`覆盖同一路径，不需要调用Circle API。

## 手动运行

```bash
pnpm community:city --dry-run
pnpm community:city
pnpm community:city --upload
```

第二条只写本地文件，开发服务器（`pnpm dev`）读的就是它；第三条同时上传到Blob并核对线上文件。脚本从环境变量、`.env`或`.env.local`读取密钥。

演示数据不调用API：`pnpm community:city --demo`。人数和热度是模拟的，名字是「示例成员00001」这样的占位，所有链接都指向立正自己的主页，页面上写明「当前为演示数据」。

## 交互

- 版式：搜索框和「随机遇见一位成员」在地图上方单独一行，左右边缘和地图对齐；地图下方是说明文字和「免费加入，一起建这座城」（英文Join free and help build it），按钮在右侧、和说明文字垂直居中，手机上排在说明文字下面。邀请说的是一起建这座城，而不是「成为一个点」。
- 动效：地图第一次进入视线时，灯从城中心（最活跃的人）向外亮起；之后有一道缓慢的明暗波、一束游走的柔光和零星闪烁的窗灯。柔光跟随鼠标，搜到某位成员时会移到TA那里。只在地图可见时运行，约30帧；系统设置减少动态效果时，地图保持静止。
- 成员卡片：第一行是名字，第二行是「2024年3月加入 · 12个帖子 · 48条评论」（英文Joined Mar 2024 · 12 posts · 48 comments）。帖子或评论为0的那一项不显示，所以只看不发的成员只显示加入月份；手机上只在两项之间换行。
- 桌面：鼠标靠近一个点，显示成员卡片；单击在新标签页打开主页。
- 手机：先点一下显示成员卡片，再点卡片打开，避免误触离开页面。
- 按名字找成员：名字以输入内容开头的排在前面，同样匹配时更活跃的在前，最多8个。上下键或鼠标移到某个结果，地图上对应的点会亮起来；回车或点击打开主页。
- 「随机遇见一位成员」随机选一位，在地图上标出并打开主页。
- 数据只在这一段接近视口时才加载；数据缺失或格式不对时，回到静态的20,000个点，搜索和随机按钮隐藏（位置保留）。
- 数据到达前，说明文字和搜索栏先占好位置（CSS里不可见的占位），所以数据到达时下面的内容不会跳动，锚点跳转也不会停错位置。
