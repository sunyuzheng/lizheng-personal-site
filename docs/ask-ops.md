# 问问立正私人Ops与问答归档

入口：`https://www.lizheng.ai/ops/ask-lizheng`。此文为已验证的本地候选，发布状态以最终review及线上核验为准。范围是私人Ops及用户新要求的问答存档；保留另一AI最新会员说明、Logto、模型、额度和主页设计。

## 访问与隐私

沿用现有Logto/邮箱验证码登录及加密会话，固定回跳`/ops/ask-lizheng`。只有`ASK_OPS_ADMIN_EMAILS`中的已验证邮箱可以读取；Founding身份不授予后台权限。入口及API仅在www.lizheng.ai工作，权限先于任何问答读取；POST删除另核验同源。浏览器只在内存保留数据，退出/失效/离开取消请求及导出并清空，迟到响应不能恢复。no-store/noindex/noarchive/no-referrer，后台停用页面分析。

## 两类数据

“旧版提问”显示现有v1真实问题、日期、模型、状态和耗时，仍按原30天期限删除。没有保存完整回答、访客标识或会话，不能补算人数/对话长度，更不能重新生成回答冒充原答案。导出为所有者管理的本地副本。

“问答归档”保存新v3提示后受理的问题、当次完整已核验回答、采用的来源快照、匿名浏览器/会话标识、服务端轮次、字数、意图、入口、状态与耗时，无TTL，持续至所有者手动删除。没有邮箱/账号/IP关联；浏览器数不等于独立人数。提交的背景和历史摘要不单独保存，回答可能引用背景，公开保存提示已说明；不保存raw provider JSON或模型内部推理。

## 写入和回看

问题在生成前可靠保存。完整回答及来源在发送SSE result前等待存档确认，生成槽提前释放；每次写入2秒、最多两次，同UUID/正文的重试幂等。无法确认保存时明确失败并退款，cleanup仍有界重试同一真实回答，不用null/error覆盖丢ACK的完整结果。崩溃或持续故障可能留下未确认结束的generating，Ops不会算作已回答。

后台按北京时间显示周期数量、状态、平均问题长度、平均耗时、每天趋势。v3另显示匿名浏览器和会话数、本期每会话提问数。展开记录回看完整答案与出处，按会话查看连续问答及当前保留轮数；服务端归档成功不等于用户收到/已读。删除确认显示具体问题，单条删除完整问答、来源及其索引/统计，24小时无正文tombstone防延迟重试复活，不提供批量删除。

列表/JSONL导出按时间与ID稳定分页。v3每页10条，控制响应大小；导出覆盖所选周期全部页及完整回答/来源。旧v1读取最多5000key/100scan/15秒，部分读取明确标记并拒绝下载不完整导出。没有后台永久复制旧v1，也不改旧TTL。

## 发布目标

个人站公开仓库main及原Vercel项目增加Ops、v3固定写入、归档提示/匿名签名。生产只新增`ASK_OPS_ENABLED=true`、`ASK_OPS_ADMIN_EMAILS=sunyuzheng@gmail.com`，沿用现有secret。

问答公开仓库main及原Builder服务同步最小v3归档支持/提示。Builder部署沿用`deepseek-v4-flash`、现行quota/query logging，增加`ASK_OPS_ENABLED=true`，不修改模型、额度、Logto或DNS。先部署个人站writer，再部署APP和启用归档，避免新协议打向旧writer。记录API从来不公开给读者。

生产发布前须审阅准确diff、两处目标及受众并明确批准。线上核验只读正式入口/权限/元数据和既有记录；不伪造owner会话、不发送邮件、不创建或删除真实用户记录。真实owner登录由所有者完成。另一个AI若再推main，需重新合并、核验与review。

## 验证

Node/Vitest、TypeScript、生产build，真实fakeredis+Lua检验原子存档、重试、删除、索引/统计与稳定分页；APP pytest检验最终ACK顺序、断线/退款/取消、大正文和旧notice隔离。浏览器只用合成问答验证登录、分页、完整回答/出处/会话、手机卡片布局、JSONL导出和退出清空。真实问题不进入Git或review截图。
