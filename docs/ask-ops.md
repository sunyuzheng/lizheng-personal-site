# 问问立正私人运营后台

入口：`https://www.lizheng.ai/ops/ask-lizheng`。本次按用户收窄的范围，只发布查看现有提问的后台，不发布问答APP、永久保存协议或公开问答UI改动。此文为候选，不能当作已上线状态。

## 权限与登录

沿用当前Logto/邮箱验证码登录入口及同一加密会话。成功后返回后台，回跳仅允许固定后台路径；无需新建Logto应用、修改凭证或扩展社区权限。唯一owner由服务端`ASK_OPS_ADMIN_EMAILS`邮箱白名单确定；Founding身份不能访问后台。核验权限先于读取任何问题，未配置或服务不可用时关闭访问。

浏览器内仅在内存保存已读取的数据，不写localStorage/sessionStorage。退出、会话失效及页面关闭时取消读取与导出并清空界面；迟到的响应不能恢复内容。页面和API均no-store/noindex，后台不启用Vercel页面分析。

## 可查看的数据

现有记录包含问题、时间、模型、结束状态和耗时。后台按北京时间提供今天、近7天、近30天及当前全部记录的数量、状态分布、平均提问长度、平均处理耗时、每日趋势，以及分页问题正文和JSONL导出。平均耗时包含失败/取消。

数量只代表目前仍保留且已成功写入的记录，不是从上线以来的总量。旧记录没有匿名访客ID、对话分组或轮次，所以无法计算独立人数和对话长度；界面显示“未记录”，不从问题文本猜测。没有保存完整回答、补充背景或模型推理。

记录仍沿用原30天过期规则，本次不复制为永久存储、不改TTL、不增加删除接口。永久保存及新的对话指标属于后续独立升级，需要配套用户提示和问答接口修改。后台导出的JSONL是所有者管理的本地副本，可以长期保留；切勿提交Git或公开分享。

读取只针对固定`ask-query:v1:`命名空间，以固定Lua批量读取现有字段并忽略读取时已过期条目；不接受任意Redis命令。扫描有数量和时间上限，触及上限时显示数据可能不完整，并拒绝下载冒充完整的导出。分页按时间与UUID稳定排序，后续页固定首次读取时间及周期，新增记录不会重排前页；导出不是事务快照，期间过期的记录可能缺失。

## 发布目标

只更新个人站公开仓库main及其现有Vercel生产项目。新增非秘密配置`ASK_OPS_ENABLED=true`、`ASK_OPS_ADMIN_EMAILS=sunyuzheng@gmail.com`；沿用现行身份与Redis配置。问答仓库/Builder不部署，模型、每日3次与网络限额、公开页面及数据收集规则均不变。

生产发布仍需精确diff、目标和受众审阅。上线后核验正式入口、未登录401、错误会员无权访问和现有Logto回跳；不创建或删除真实用户提问，不发送测试邮件或伪造owner会话。登录后读取数据由所有者完成。

`pnpm test:ask-lizheng`、`pnpm check`、`pnpm build`，并用隔离的fakeredis测试固定Lua实际行为。浏览器只使用合成记录验证登录入口、分页、手机布局、导出和退出清空；不把真实提问放入截图或测试日志。
