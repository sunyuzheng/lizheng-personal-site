# lizheng.ai 内容系统

本文档说明各个公开页面分别承担什么任务、哪些信息由谁维护，以及如何避免个人主页、产品站和 GitHub 彼此重复或口径漂移。

## 一条主线

个人主页的中心不是一份产品目录，也不是履历或粉丝数。它要回答的是：

> 一个判断怎样进入现实、接受反馈，再变成别人真正能使用的能力、作品和系统。

首页从这条长期主线里，选择一个更具体的 AI 时代入口：

> AI makes building easier. My focus is studying what’s worth building.
>
> AI让「做出来」越来越容易。我研究的是：什么值得做。

这不是另起一套个人主张，也不是说实现、可靠性、采用和组织改变已经变得简单。首页的 presentation hierarchy 是：

1. **AI让「做出来」越来越容易：**更多想法能以更低的执行成本进入可工作的形态；
2. **研究什么值得做：**先判断它对谁有用、要改变什么、为什么值得投入；
3. **让现实检验判断：**交给用户、产品、实验、组织和公开讨论来挑错；
4. **让有用的部分复利：**把经得住检验的部分沉淀成能力、课程、流程、产品、书、工具、关系或其他可复用系统。

Hero 只承担前两层，后两层由经历、公开判断、当前工作、书和访谈证明，不再叠加另一句同等分量的口号。`Build AI systems that compound` 仍然是 AI 工作的一条主张，但不承担整个人主页的首屏定位。

首页的阅读顺序是：

1. 先看到 AI 正在改变执行成本，以及“什么值得做”这个个人研究问题；
2. 再看到这套判断怎样从经济学、产品、管理和实验经历中形成；
3. 接着看判断如何进入现实，以及有时间戳的公开记录；
4. 然后看经得住检验的部分怎样被教成能力、放进长期环境、用于企业现场；
5. 最后由访谈、书、社区结果和同行评价完成第三方验证，并说明哪些东西已经能够持续复用和复利。

不是先宣布“权威”，再找材料支持；而是先给事实和场景，帮助读者理解它说明什么，再把结论留给读者。

## 中文混排

网站自行撰写的中文正文、界面、meta与结构化数据，在中文和英文、数字相接时不留空格，例如`AI教育`、`2026年`和`200+场`。英文品牌或人名内部原有的空格保留，例如`AI Builders`和`Ben Gilbert`。

如果去掉空格会让名字、机构或职位粘成一串，使用括号、冒号或`·`明确关系，例如`贾扬清（Yangqing Jia）`、`Statsig · Principal Data Scientist`。节目原名、视频标题、嘉宾资料源和直接引语按来源保留，不做机械改写。

AI Builders 是最能代表这条主线的产品：它显示立正与鸭哥如何把模型、工程、产品和组织里形成的理解，拆成别人能够理解、练习、纠错，最终带回自己问题里的能力。个人主页可以讲这个转化，并在原地放一条足够说明教学结果的证据；不复制课程站的 55 个项目、600+ 社区项目、评价墙或购买权益。需要展开时，优先做独立 Teaching / Education case，而不是继续拉长首页。

Stay Superlinear 不是“课程之后继续付费”的尾巴，也不是用来证明主理人有号召力。它承担另一件事：让已有专业积累的人持续带着手头的工作、作品和问题回来，在一手经验、反馈、关系和机会中更好地判断下一步。

## 证据怎么放

权威是读者根据事实作出的判断，不是页面自封的身份。首页遵循四条规则：

1. **每条证据只做一件事。** 3,000+ 与 Maven 评分回答“能不能教会别人”；DoorDash 现场回答“能不能进入真实组织”；200+ 场对话回答“判断从哪里继续获得一手输入”。
2. **证据放在问题发生的地方。** 学员数字跟着 AI Builders，受众与对话数字跟着访谈，社区行为跟着社区，WSJ 书单跟着书；不再单独做一面数字墙。
3. **只解释必要的一步。** 说清一个事实说明哪种能力、为什么与此处有关；不把同一段履历或同一组数字在多处重复。
4. **保留边界。** 雇主不是个人背书，流量不是观点正确，过往判断也不等于永远看得准。日期、合作归属和证据限制都要可见。

首页因此采用 `show → frame → let the reader conclude`：给出事实或场景，补一层必要的解释，然后停住。

## 页面分工

| 页面                   | 首要任务                               | 不承担的任务                           |
| ---------------------- | -------------------------------------- | -------------------------------------- |
| `/`                    | 建立人物主线与选择性证据               | 罗列全部项目、全部嘉宾或完整销售论证   |
| `/zh`                  | 中文主页；与英文首页使用独立 canonical | 作为 query parameter 版的附属翻译      |
| `/about` · `/zh/about` | 中性人物事实、履历、项目关系与口径澄清 | 复制首页的人物叙事或产品转化           |
| `/book`                | 说明两本书分别解决什么问题             | 复制单书销售页                         |
| `/zh/book`             | 两本书的中文 canonical 页              | 依赖 `?lang=zh`                        |
| `/zbs`                 | 介绍《真本事》、购买入口与 AI 顾问     | 保存发布期排名、价格和会过期的个人简介 |
| `/guests`              | 完整的访谈人物与内容档案               | 把所有嘉宾都包装成“科技领袖”           |
| `/collab`              | 演讲、企业项目、顾问与长期合作分流     | 接受播客邀请                           |
| `/collab/creators`     | 英文节目邀请与 host kit                | 泛合作入口                             |
| `/zh/collab/creators`  | 面向中文播客与视频主的主要邀请页       | 产品销售页                             |

creator 页面是公开、持续更新的 canonical host kit。新 PDF 是由该页面与个人事实源派生的离线商务附件，供商务负责人直接转发：

- 当前 PDF：`output/pdf/课代表立正_播客与视频访谈资料_2026-07.pdf`
- 生成源：`scripts/generate-podcast-collab-pdf.py`
- 旧 `/collab/podcast-one-pager.pdf` 与旧 Stay collateral 继续退出，只保留永久跳转或历史归档。

网页更新后应检查 PDF 是否需要重生成；PDF 不反向成为人物或产品事实源。

## GitHub 的任务

GitHub 不复制整页个人叙事。它负责回答一个更窄的问题：这个人实际公开做出了什么、愿意把哪些系统交给别人使用？

Profile README 只需要：一句身份、当前三项工作、精选公共项目、书与公开内容入口、Seattle 和联系方式。置顶仓库优先选真实可用、边界清楚、README 完整的工具，不按 stars 机械排序。

## 更新检查

公开发布前依次检查：

1. 新数字是否已经进入 `yuzheng-profile/facts.json`，并附 `as_of` 与证据。
2. 是否误把 Statsig 被 OpenAI 收购写成孙煜征加入 OpenAI。
3. 是否混淆免费 Superlinear Academy 与付费 Stay Superlinear。
4. 是否把对话场次写成嘉宾人数。
5. 是否使用 `staysuperlinear.com`、`ai-builders.com` 和 `www.lizheng.ai`。
6. 页面 title、description、canonical、OG、sitemap 与正文是否一致。
7. 核心页源 HTML 是否包含真实正文，中英文页是否 reciprocal hreflang。
8. sitemap `lastmod` 是否只反映真实内容变更，不是构建日期。
9. `pnpm check` 与 `pnpm build` 是否通过。
10. 公开部署、GitHub 资料修改和归档操作是否已经单独审阅并获批。
